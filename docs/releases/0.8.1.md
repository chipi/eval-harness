# 0.8.1, in full

The full notes of 0.8.1; its section in the [CHANGELOG](https://github.com/chipi/eval-harness/blob/main/harness/CHANGELOG.md)
is the short version. No result moves: no scorer, statistic, fingerprint or data format changed.

## Added

- **The Workbench, read-only, for visitors to a deployment**
  ([RFC-039](../rfc/RFC-039-workbench-read-only-for-visitors.md)). A public server serves `/workbench/` and the
  `/api/v1` operations that only read, the same set the public MCP server answers, under the same text rules
  (`text: hidden`, `--publish`) and rate limit. Everything that writes, spends or runs a model, `POST /estimate`,
  `/jobs` and `/session` is refused at the server. The page draws no control that acts, says on every screen that it is
  a read-only view, and leaves out of its menu the screens whose only job is to act. `evh catalog-serve --catalog-at
  PATH` says where the deployment serves the catalog (`/catalog/` on this repository's), so the Workbench's links to
  it go there; the default is `/`. A project's own server is unchanged.
- **Where the judge disagrees with the gold, per item.** An item disagrees when its own term of the judge's validation
  figure (`evh judge-validate`) is under that figure's chance level: Kendall's tau under 0 (grade), top-1 under the
  item's chance (pick), pair agreement under 0.5 (pairwise). The inspector's item view says "judge vs gold: agrees" or
  "disagrees"; the sheet marks the rows and filters them (`only=judge`); `evh comparison-items` and `evh sheet-export`
  take `--judge-disagrees`. A public server shows it only when it publishes both outputs and references.

## Changed

- **`evh catalog-serve` renders each page when it is asked for**
  ([RFC-040](../rfc/RFC-040-catalog-rendered-on-request.md)). A write through the Workbench, the API, MCP or the command
  line is on the next page opened: no `catalog` job runs, and no page shows the data from before a rebuild. The server
  needs no `evh catalog` first. A page is rendered from one model of the data, kept until the data changes (2.3 s to
  make on this repository's runs); the home page, the goals page and each goal's page are rendered ahead after a change.
  `evh catalog` writes the same pages as files, byte for byte, for a host with no server; it is also faster (13 s to
  8 s here), since a goal's decisions and the model records are read once for every page that shows them. `GET /api/health`'s `catalog` is
  now `{mode: "on request", state: idle | failed, built_at, prepared, failed}`: `building`, `job` and `queued` are
  gone. A deployment with `--public` is unchanged.
- **The inspector names arms by one rule everywhere.** The sheet used to keep a shared prefix; it now drops only the
  dataset's own words, as every other view does. A path name keeps its system id (`rescored-…/…/triage_baseline_pro_v1`
  reads `baseline_pro_v1`); two arms left with the same name keep their paths.
- **A scatter's names never cover a dot or another name.** A name sits beside its dot where it covers neither; else it
  moves to the nearest clear place within four lines, with a leader line to its dot; else the caption names it.
- **"See the cost first" shows the figure.** Each arm's `ESTIMATE ~$…` and the cap the Workbench will send are shown
  above the dry run, which is folded. Before, they were below the fold of a scrolling box, and the line shown for the cap
  was the estimate's own (`NONE`), not the one typed.
- **`evh runs-list` tells an unknown tree from a clean one.** A run made with `EVAL_BUILD_REF` set, or brought in by
  `evh import-run`, records `build.dirty: null`; `runs-list` showed it as clean. The table now marks it `?` with a legend
  line, and `--json` carries `dirty: true | false | null`. A record with no `build` reads as unknown (it raised
  `KeyError`). Read null as "unknown" if you read `dirty` from `runs-list --json`.

## Fixed

- **`check_hf_source.py` (the examples' rerun job)** retried any error for 30 seconds, a 4xx included. It retries a 5xx,
  a dropped connection and a timeout for about two minutes, says each retry, fails a 4xx at once, and ends in one line,
  never a traceback.
- **`make site`** removed `site/public` and wrote in place for two minutes, so an interrupted build left it mostly
  deleted. It builds beside it and swaps in a whole build.

## The repository and its release

- **A merge to main deploys nothing.** `deploy-prod.yml` runs only when dispatched, with the commit it is for; its first
  step refuses any other commit. `make deploy-dry`, then `make deploy`, which refuses unless a dry run of that same
  commit passed. The repository variable `PROD_AUTO_DEPLOY`, which let a push deploy, is deleted.
- **A release's notes are short.** From 0.8.0 a CHANGELOG section is at most 4,000 characters and links its full notes
  here, in `docs/releases/` (checked by `site-check`). 0.8.0's 161,773 characters moved to
  [0.8.0.md](0.8.0.md).
- **Tests that fail only for a reason.** The Workbench's paid run is tested end to end against a local provider that
  bills (estimate, cap, round budget, spend, `build.dirty`, `runs-list`, 390 px). The inspector and the real catalog
  are browser-tested on SQLite as well as files. Every browser test lays pages out in one bundled font (Lato, SIL OFL
  1.1), so a layout check fails at the same width on any machine. Two tests that failed under load wait on the state they
  need: a timing check compares structure, not two clocks, and a page load is asked again only when Chromium reports the
  machine's network changed.
- **A release tag could move.** The `release tags` ruleset let a repository admin bypass its `deletion` rule, and a tag
  deleted could be created again on another commit, as `v0.8.0` was on 2026-11-22 (from `448d34baa` to `094aa680a`,
  before any Release named it). The ruleset now has no bypass: it holds for an admin too, and RELEASING.md says how a
  mistaken tag is fixed on purpose.
