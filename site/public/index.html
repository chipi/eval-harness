Is the ranking real, or a lucky sample?

A small, drop-in harness for evaluating AI systems on your own data. Freeze a dataset, run your system against it, and get the answer most leaderboards skip: whether one system is actually better than another, or only ahead on this sample. This is ongoing work: the harness and its method are the point, and the six experiments are worked examples of them, not a benchmark.

03

Do I need an LLM — or a GPU — at all?

What it foundA free model that needs no GPU was first, or not separable from first, in 5 of 6, against LLMs run with one prompt and no examples; the clearest wins were on text like the text it was trained on. On judging summaries even a free model trained for the task lost, and an LLM judge scored above every free scorer measured: judging summaries, the best LLM judges reach 93% of a human expert's agreement (the best of 24, chosen on the same articles; 92% held out), and UniEval, the best free scorer, 64%. A no-model lookup of which system wrote each summary reaches 63%; the summaries are 2019-era and the judges ran with reasoning off. One task, so the direction, not the size.

02What it does

Four ideas, one adapter file.

Most eval code answers “which scored highest”. That is the easy half; the hard half is whether the answer survives being asked again. The harness imports nothing domain-specific — everything about your system lives in one file, adapter.py, with four functions.

01A frozen datasetItems are hashed and every run records the hash. Change the data and you get a different id — not a silently different number.
02A fingerprint per runThe model behind the alias, the prompt, the scoring code, library versions, the commit. So “we changed one thing” is checkable, not asserted.
03A leaderboard that argues with itselfBefore it prints an order it tests every pair at once — a Friedman permutation test and a Nemenyi critical difference — and says plainly when nothing is distinguishable.
04Re-scoring for $0Scores are recomputed from stored outputs. Checking a metric should never cost another sweep of paid calls.

Try the whole loop in a minute.

The demo runs on bundled synthetic data — no API key, no network. It freezes a dataset, runs an arm three times and checks the record; make leaderboard then shows the ranking and whether it is real.

Your first evaluation — the guide
$ git clone https://github.com/chipi/eval-harness
$ cd eval-harness/harness
$ make install
$ make demo
$ make leaderboard
# then, on your own system
$ make dataset-create DATASET_ID=my_v1
$ make experiment-run CONFIG=data/configs/arm_a.yaml
$ make leaderboard DATASET_ID=my_v1

04The method

The harness enforces a method.

Nothing here needed special access or a big budget. It took six habits — each learned by getting something wrong first — and a harness that enforces them. They work on any problem you can put into a dataset. The framing builds on Chip Huyen's AI Engineering and Designing Machine Learning Systems.

01An eval is an experiment.Vary one thing. Record everything else.02The data is the instrument.Freeze it, hash it, check it against the world.03Silver is not gold.A model's answers rank; a person's answers judge.04Measure the noise before the difference.A delta below an arm's own jitter is nothing.05Tested, not read.Say separated, not higher.06Decide on the record.The scorer is part of the experiment. So is the reason.
