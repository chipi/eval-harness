eval-harness · open source · MIT · by Marko Dragoljevic

Is the ranking real, or a lucky sample?

A small, drop-in harness for evaluating AI systems on your own data. Freeze a dataset, run your system against it, and get the answer most leaderboards skip: whether one system is actually better than another, or only ahead on this sample.

This is ongoing work: the harness and its method are the point, and the six experiments are worked examples of them, not a benchmark.

Three parts: this site, why the harness exists and what it found; the catalog, the harness's own pages over every run behind it, with an inspector that re-tests any comparison; and the docs, how to do the same on your own system.

01Why the harness exists

Four questions anyone building with AI ends up asking.

There are dozens of models, a leaderboard for each, and none of them measured on your problem. The harness exists to answer these on your own data; below, what it answered when pointed at 24 LLMs. How it does that is in the method.

Which model is best for what I need — not for someone else's benchmark?

What it foundOn each experiment's primary metric the most expensive model was not the best in any of the 5 experiments where frontier models ran (the same model each time; SciFact ran only the twelve cheapest hosted models); re-measured, against corrected labels and by LLM judges, it is first on the point estimate in two, neither re-measurement confirmed. 03

Do I need an LLM — or a GPU — at all?

What it foundA free model that needs no GPU was first, or not separable from first, in 5 of 6 on the primary metrics (3 of 6 on the re-measured scores, unconfirmed), against LLMs run with one prompt and no examples; the clearest wins were on text like the text it was trained on. On judging summaries even a free model trained for the task lost, and an LLM judge scored above every free scorer measured: judging summaries, the best LLM judges reach 93% of a human expert's agreement (the best of 24, chosen on the same articles; 92% held out), and UniEval, the best free scorer, 64%. A no-model lookup of which system wrote each summary reaches 63%; the summaries are 2019-era and the judges ran with reasoning off. One task, so the direction, not the size.

02What the harness does

Six ideas, one adapter file.

Most eval code answers “which scored highest”. That is the easy half; the hard half is whether the answer survives being asked again. The harness imports nothing domain-specific — everything about your system lives in one file, adapter.py, with two functions you write: call_system() and score().

01A frozen datasetItems are hashed and every run records the hash. Change the data and you get a different id — not a silently different number.
02A fingerprint per runThe model behind the alias, the prompt, the scoring code, library versions, the commit. So “we changed one thing” is checkable, not asserted.
03A leaderboard that argues with itselfBefore it prints an order it tests every pair at once — a Friedman permutation test and a Nemenyi critical difference — and says plainly when nothing is distinguishable.
04Re-scoring for $0Scores are recomputed from stored outputs. Checking a metric should never cost another sweep of paid calls.
05A goal that recommendsA goal says what the evaluation is for: the measure that decides, limits on cost and speed, how a tie is broken. Its rule recommends an arm and says why; a person promotes the baseline, the run later changes are measured against.
06A catalog to look around inThe harness builds pages over your committed runs: every goal with what it recommends, every dataset, arm, reference and metric, and an inspector that compares any arms item by item. Every view is also an evh command. Ours, on the six worked examples →

Try the whole loop.

Install the pinned release in a new folder; evh init --tutorial writes the project's folders and a six-ticket tutorial kit, and getting started takes it through the loop in about fifteen minutes — a dataset, arms, a reference from the best arm's run, a comparison, a choice — offline, no API key. Tutorials then add a local model, a hosted LLM with your own key, a frontier reference and judges, and rounds. Last, look at it all: evh catalog builds the catalog of your own runs and evh catalog-serve opens it with the inspector (tutorial 5); ours shows the six worked examples. From a checkout of this repository, make demo runs the loop on bundled synthetic data in a minute.

Getting startedThe tutorialsThe catalog
$ pip install "evaluation-harness @ git+https://github.com/chipi/eval-harness@v0.4.4#subdirectory=harness"

# the guide walks the tutorial from here; then, on your own system

$ cd eval-harness/harness
$ make install
$ make demo

03Worked examples · 24 LLMs

The most expensive model never won.

These are examples of the harness and its method at work, not a leaderboard, and they are still being extended. To show the harness doing something real, it measured 24 hosted LLMs, proprietary and open-weight from small to frontier tiers, small fine-tuned models and baselines on six public benchmarks — 167 runs, $19.07 billed, every cost read off the provider's bill. The headline is on each experiment's primary metric. Re-measured, against labels a person corrected and by LLM judges, the dearest model, anthropic_l, is first on the point estimate in two: AG News and CNN/DailyMail; neither re-measurement is confirmed. For agents

Ask it from your agent.

The harness is also an MCP server. evh mcp gives an agent the same read commands you use: datasets and what is inside them, goals and what they recommend, arms, references, metrics, activity, and the inspector's paired comparisons, each answering exactly what the command prints. Nothing it does writes, spends or runs a model.

On your machine it serves your own project; for a team, evh mcp --http serves one checkout to everyone. The worked examples above are served at https://evals.humancopilot.eu/mcp, read-only and without sign-in, for Claude, ChatGPT and the OpenAI API, Gemini, or any MCP client.

Connect an agentHow it works
# the worked examples, from Claude Code
$ claude mcp add --transport http evals https://evals.humancopilot.eu/mcp
# your own project, on your machine
$ claude mcp add evh -- evh mcp
# a team's server
$ evh mcp --http --bind 0.0.0.0 --allowed-host evals.team.example
04The method

The harness enforces a method.

Nothing here needed special access or a big budget. It took six habits — each learned by getting something wrong first — and a harness that enforces them. They work on any problem you can put into a dataset. The framing builds on Chip Huyen's AI Engineering and Designing Machine Learning Systems.

01An eval is an experiment.Vary one thing. Record everything else.02The data is the instrument.Freeze it, hash it, check it against the world.03Silver is not gold.A model's answers rank; a person's answers judge.04Measure the noise before the difference.A delta below an arm's own jitter is nothing.05Tested, not read.Say separated, not higher.06Decide on the record.The scorer is part of the experiment. So is the reason.
